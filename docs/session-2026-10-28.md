# Sendlog: build notes (28–29 Oct 2026)

Sendlog was called **GritMark** until 29 Oct 2026. The GitHub repo was renamed to `matheusmsil/Sendlog` on 30 Oct 2026; the folder on disk is still named `GritMark`.

## What you asked for

An app for logging fitness training:
- **Strength training:** how much weight you lifted and how many rounds (sets).
- **Climbing training**, for example:
  - 5 different boulders, twice each, using only one leg
  - a circuit: climb each boulder once
- Ideally, pull exercise data from your **Apple Watch**.

Later additions:
- Activation and mobility blocks inside any session.
- Stats to see how you're improving.
- An app icon.
- A new name: Sendlog.
- Pro-level dashboards for improving as a climber.
- Templates ("plans") for the sessions a coach sends, started with one button.
- A selectable period size on the Log page.
- The coach's program (Manual da Escalada 001, PDF) loaded as plans, the whole app in Portuguese, and a gym field.

## What was built

A native iPhone app (SwiftUI + SwiftData + Swift Charts, iOS 18+). Reading Apple Watch workouts requires Apple's HealthKit, which only native apps can use, so it couldn't be a web app.

### Strength sessions
- Add exercises from a preset list (Squat, Deadlift, Bench Press, Overhead Press, Pull-up, Barbell Row, Dips, Lunges, Hip Thrust, Hangboard) or type a custom name.
- Each set has a weight (kg) and reps. "Add set" copies the previous set.
- Each exercise shows its total sets, reps and volume (weight × reps).

### Climbing sessions
A session is made of **blocks**. Each block has a format and an optional variation.

| Format | Meaning |
|---|---|
| Circuit | Climb each boulder once |
| Repeats | Climb each boulder N times |
| Projecting | Count attempts on a hard problem, mark it sent |
| Free climbing | Log whatever you climbed |

- Variation presets: One leg, One arm, No feet, Silent feet, Hover hands, Downclimb, Flash attempt, or type your own.
- Each boulder has a name, a grade and one tappable circle per planned ascent.
- Example: your one-leg drill = Repeats, 5 boulders, 2 times each, variation "One leg".

### Activation & mobility blocks
- Any session (climbing, strength or other) can have **activation** and **mobility** blocks. They appear above the main training.
- **Activation presets:** band pull-aparts, scapular pull-ups, shoulder external rotations, glute bridges, dead bug, finger rolls, wrist circles, easy traverse.
- **Mobility presets:** hip flexor, pigeon, frog and couch stretches, deep squat hold, hamstring stretch, thoracic rotations, shoulder dislocates, wrist & forearm stretch.
- Custom exercises are also possible.
- Each exercise has a number of sets, an amount in reps or time, and a circle to tick when done.
- In the session list, a ⚡ or stretch icon shows which sessions included them.

### iCloud backup (30 Oct 2026)
- **No login.** Data syncs to the private iCloud database of the Apple ID signed in on the iPhone, using SwiftData + CloudKit, container `iCloud.com.matheus.Sendlog`.
  - Changing phones: sign in with the same Apple ID, install Sendlog, and the sessions and plans come back.
  - It also keeps two iPhones/iPads in sync.
- **Synced:** sessions, plans, blocks, boulders, sets, notes, gyms, video links.
- **Device only:**
  - Apple Watch calories and heart rate. These are in a separate local store (`health.store`), because Apple forbids storing Health data in iCloud. Duration and date stay in the synced session.
  - Bodyweight and screen preferences (`UserDefaults`).
- **Backup screen:** the cloud button at the top left of **Treinos** shows whether iCloud is active and what is and isn't backed up.
- **No duplicate plans:** the coach's program plans have fixed IDs, so a new phone that installs them before iCloud delivers the old ones keeps only one copy.
- **On/off switch:** iCloud and Push need a paid Apple Developer Program team; a free (personal) team can't sign them. The build setting **`SENDLOG_ICLOUD`** (target Sendlog › Build Settings › User-Defined) controls it:
  - **`NO`** (current default) signs with `Sendlog-Local.entitlements` (HealthKit only), and the app stores data on the device only.
  - **`YES`** signs with `Sendlog.entitlements` (iCloud + CloudKit + Push) and turns sync on.
  - The app reads the setting through the `SendlogICloudSync` key in `Sendlog-Info.plist`. This matters because touching CloudKit without the entitlement makes iOS kill the app; it can't be caught in code.
- **If iCloud is on but can't start**, the app falls back to local-only storage instead of crashing.
- **Existing data was kept:** the store file is unchanged (`default.store`). Models now give every field a default and make relationships optional, as CloudKit requires (`exerciseList` etc., wrapped by the old `exercises` names).
- **Before release**, in the CloudKit Console:
  1. Run the app once on a device signed into iCloud.
  2. Deploy the development schema to **Production**.
  3. Never rename or delete synced fields after that, only add new ones.
- **Recovery (HRV and resting heart rate) was removed** from the Progress tab, and Sendlog no longer asks Health for those types.

### Plans (templates)
- The **Plans** tab holds sessions you write once, such as your coach's program. Each plan has:
  - a name
  - a type
  - activation, mobility, climbing or strength blocks, with sets and weights
  - **Coach notes**
- Plans use the same editor as a session, minus date, effort and Apple Watch.
- Tap **Start** on a plan to create today's session from it and open it in Log, ready to tick off.
- The coach notes show at the top of the session.
- Each plan shows how many times you've done it and when you last did it.
- Other ways to start or create plans:
  - **+ › Start a plan** on the Log page starts one without leaving Log.
  - The **•••** menu on any logged session has **Save as plan**, to turn a session into a plan.
  - Swipe a plan to **Duplicate** it (e.g. to make a variation) or **Delete** it.
- Plans never count in your stats.

### Log page periods
- The summary at the top of Log has a **Week / Month / 3 months / Year** picker, and the list below shows only the sessions in that period.
- The ‹ › arrows go back to earlier periods (e.g. last month, September 2026).
- It shows:
  - sessions, climbing, strength and training time
  - ascents, hardest send and training days
  - how the session count compares with the previous period
- The period size is remembered. The default is Month.

### Boulder tags
Each boulder row has a tag button next to the grade. It sets:
- the **wall angle**: slab, vertical, overhang or roof
- the **hold types**: jug, crimp, sloper, pinch, pocket or volume
- **Flashed**: sent first try. In Projecting blocks, a send with exactly 1 attempt counts as a flash automatically.

Tags are optional, but the style and weakness analysis needs them. Repeat keeps the angle and holds.

### Progress tab: four dashboards
Each dashboard can show 4 weeks, 12 weeks, 6 months or 1 year. Tap a bar, point or square to see its numbers.

**Overview**
- total sessions, training time, week streak and average effort
- sessions per week by type
- how often you did activation and mobility

**Climbing**
- **Performance**
  - hardest send, compared with the previous period of the same length
  - flash grade: the hardest boulder sent first try
  - consolidated grade: the hardest grade sent 3+ times
  - send rate
  - ascents per week
- **Grade pyramid:** sends per grade, split into flashed and worked. It comes with advice, such as whether the base under your max grade is wide enough to push higher.
- **Progression**
  - hardest send and typical (median) send per week
  - average attempts to send per grade, from Projecting blocks
- **Style**
  - send rate by wall angle and by hold type, using climbs within 2 grades of your max so warm-ups don't skew it
  - a "Train next" weakness and a "Strength" highlight
- **Projects:** named boulders in Projecting blocks, followed across sessions (attempts, sessions, sent date). Use the same name each session.

**Load**
- **Training load** = effort (RPE) × minutes, per week and by type, with training and rest days.
- **Acute : chronic load:** the last 7 days vs your 4-week average.
  - The zones are detraining, sweet spot (0.8–1.3), ramping up, and high injury risk (above 1.5).
  - It needs 4 weeks of logged history before it appears.
- **Training calendar:** one square per day, shaded by load.

**Strength**
- **Fingers & pulling:** strength-to-weight = (bodyweight + added weight) ÷ bodyweight.
  - It reads strength exercises named "Hangboard" (or anything containing "hang") and "Pull-up".
  - Bodyweight can be typed in or read from Apple Health.
- The per-exercise charts from before: best set, estimated one-rep max, heaviest set over time, and volume.

Chart colors stay the same everywhere (climbing blue, strength orange, flash yellow) and were checked for color-blind readability in light and dark mode.

### Apple Watch (Apple Health)
- **+ → Import from Apple Watch** lists workouts from the last 30 days and creates a session from the one you pick. It fills in date, duration, active calories, and average and max heart rate. Climbing workouts become climbing sessions; strength workouts become strength sessions.
- **Link Apple Watch workout**, inside a session, attaches watch stats to a session you already logged.
- Workouts that are already logged show as "Logged" and can't be imported twice.

### Other features
- Every session has a title, type, date, duration, effort (RPE 1–10) and notes.
- The home screen groups sessions by month and shows this week's totals (sessions, climbing, strength, minutes).
- Swipe a session left:
  - **Repeat** starts a new session with the same exercises, weights, boulders and activation/mobility blocks, with progress reset.
  - **Delete** removes it.

### App icon
- An orange climbing hold shaped like an **S**, bolted to a gym wall. The bolt is in the middle of the S.
- There are three versions, and iOS picks one based on your home screen setting:
  - **Normal:** orange hold on a light wall
  - **Dark:** orange hold on a dark wall
  - **Tinted:** white hold on a black wall, recolored by iOS
- The icon is drawn by `tools/render_icon.swift`, so you can tweak colors or shape there and regenerate it (see below). It doesn't use Apple's SF Symbols, which apps aren't allowed to use in icons.
- Earlier versions were a check mark climbing into mountain peaks, then a G-shaped hold (for GritMark).

## Running it on your iPhone

1. Open `Sendlog.xcodeproj` in Xcode. If Xcode still has the old `GritMark.xcodeproj` open, close it first.
2. Your signing team is already set. If Xcode says the bundle ID `com.matheus.Sendlog` is unavailable, change it under the Sendlog target → **Signing & Capabilities**.
3. Plug in your iPhone, select it as the run destination, and press Run.
4. The first time you import from Apple Watch or tap the Health button next to bodyweight, allow Sendlog to read the Health data it asks for.
5. If you denied access by mistake, go to Settings › Health › Data Access & Devices › Sendlog.

Because the bundle ID changed with the rename, iOS treats Sendlog as a new app. If GritMark was ever installed on your iPhone, its logged sessions stay in that old app, and you can delete it.

## Handy commands

- **Try it with sample data:** in Xcode, go to Product › Scheme › Edit Scheme › Run › Arguments and add `-seedSampleData`. This fills an empty app with 12 weeks of example training, including tagged boulders, projects and hangboard sessions (debug builds only).
- **Open on the Plans tab:** add the `-openPlans` argument. The sample data includes two plans.
- **Open on the Progress tab:** add the `-openProgress` argument. Add `-dashboard climbing` (or `load`, `strength`, `overview`) to pick the dashboard.
- **Regenerate the icon:** run this from the repo root:
  `swift tools/render_icon.swift Sendlog/Assets.xcassets/AppIcon.appiconset`

## Known limitations

- Weights are always in kg (no lb option).
- The app doesn't record workouts. Start the workout on your Apple Watch, then import it.
- Activation and mobility blocks always appear above the main training; there's no option to place mobility after it as a cooldown.
- In "Sessions per week", the stacked bar segments have no small gap between colors.
- Grades are analysed on the V-scale. Font grades are converted, but charts always show V grades.
- The code hasn't been committed to git yet.
